# Apollo Growth Autonomy: Chat to Foundry

Status: experimental feature in PR #40; not merged or installed.
Depends on the normal-chat Growth Lab / Pile routing repair from PR #38.

## What normal chat can actually do

1. A question about earning Apollo upgrade money shows three scoped local demo ideas.
2. Only an explicit reply such as 'begin Apollo project 1' creates a Growth Lab proposed work item and a genuine Foundry project. A one-use, 24-hour offer is required.
3. With permission, Apollo attempts ONE bounded local Ollama implementer draft, stages allowed project-local source files, runs Foundry static UI/backend checks and records actual results.
4. 'status Apollo project' reports persisted project IDs, generated files, task states and blockers.
5. 'pause Apollo project' prevents further chat-driven steps; 'continue Apollo project' authorises one bounded retry. An in-flight model call may finish before pause takes effect.
6. Open the generated Foundry project and separately authorise 'Start Continuous Session' for multi-agent drafting, meetings and restricted Docker testing while Apollo is open.

## Unbreakable boundaries

- Generated project code is untrusted. Static checks do NOT mean functional/runtime correctness.
- The chat mission cannot run arbitrary generated code, contact real clients, send marketing, accept payments, buy hardware, deploy products or change Apollo core.
- The Growth Lab work record remains proposed and estimated earnings start at zero.
- Failed drafts become blocked with durable evidence. Explicit owner review is required to accept the project or use its deliverables.
- Database writes across Foundry and Growth Lab are not atomic; retained partial records are reported instead of silently deleted.
- There is no unattended daemon or automatic resume after an application restart.
- Pausing the chat mission does not pause an independently authorised Foundry continuous session; use Foundry's Pause/Stop controls for that.

## Follow-on work toward useful autonomy

- Durable shared mission queue and explicit scoped capability permissions across agents.
- Repeated isolated code reviews and Docker/UI tests with measurable quality thresholds.
- Saved product packaging, README, demonstration datasets and real screenshots for human review.
- Research genuine customer demand, calculate build/maintenance costs and compare viable prices with evidence.
- Obtain user approval before outreach, publishing, contracts, financial commitments, purchases or production upgrades.
- Log delivered jobs, true revenues, costs and outcomes to improve future project prioritisation.

Acceptance: the assistant responds with actionable product offers instead of generic career advice; an explicit start command creates a project and attempts work; actual source/verification is shown; blocked work never becomes a fake success.
